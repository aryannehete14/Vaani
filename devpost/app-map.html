App map

Vaani

A shop owner describes their shop out loud. Vaani turns the words into a structured shop, shows it as a live preview, and publishes a page where customers can browse, check if the shop is open, and send an order on WhatsApp.

The main pieces

Web app (React)

The screens: builder, live preview, published page, owner dashboard and the customer shop. Lives in client/src.

AI engine

Turns a transcript into a checked shop. Claude when a key is set, the offline rule parser otherwise. Lives in server/src/ai.

Server and database

Express API plus a SQLite file that stores shops and customer messages. Lives in server/src, data in server/data/vaani.db.

A practice to reuse

Put a checked gate and a plain fallback after every AI call, and test the failure on purpose.

In Vaani, both engines return to one function, normalizeStore, which validates against StoreSchema (server/src/ai/schema.js). The test pipeline falls back to rules when Claude fails in server/test/ruleParser.test.js hands the pipeline a fake Claude that throws and checks a valid shop still comes back. Another test, generated stores never contain emoji or em dashes, turns a design rule into something the computer checks.

On another project with an AI step, the same pattern keeps a bad or missing AI answer from breaking the app: decide the shape you need, check every answer against it, keep a simple non-AI path, and write one test that makes the AI fail.
